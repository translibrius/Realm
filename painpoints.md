│ 1. No Draw Call Batching / Immediate-Mode Rendering (Renderer)                                                                                                                                                                                                                                                  │
│                                                                                                                                                                                                                                                                                                                 │
│ Why it's #1: This is the single biggest performance ceiling. Every mesh triggers its own shader bind + uniform uploads + draw call. Once you have hundreds of objects, this kills frame time.                                                                                                                   │
│                                                                                                                                                                                                                                                                                                                 │
│ What's happening:                                                                                                                                                                                                                                                                                               │
│ - gl_renderer.c:53-84 — loops over meshes, calls opengl_shader_use() + 7× glGetUniformLocation() per mesh per frame                                                                                                                                                                                             │
│ - Uniform locations are looked up by string every frame (gl_shader.c:47-77) instead of cached at compile time                                                                                                                                                                                                   │
│ - No sorting by shader/material — a lit mesh followed by an unlit mesh followed by a lit mesh = 3 shader switches                                                                                                                                                                                               │
│ - Vulkan side has the same conceptual issue: one UBO update per frame, no instanced or batched rendering                                                                                                                                                                                                        │
│                                                                                                                                                                                                                                                                                                                 │
│ What to fix:                                                                                                                                                                                                                                                                                                    │
│ 1. Cache uniform locations in GL_Shader struct at link time (a i32 loc_model, loc_view, loc_projection, ... approach or a hash map)                                                                                                                                                                             │
│ 2. Sort meshes by shader/material before submitting to backend                                                                                                                                                                                                                                                  │
│ 3. Instance rendering for identical meshes (your floor tiles are a perfect candidate — FLOOR_TILE_COUNT identical cubes)                                                                                                                                                                                        │
│ 4. Batch uniform uploads — set view/projection once per shader, not per mesh                                                                                                                                                                                                                                    │
│                                                                                                                                                                                                                                                                                                                 │
│ Files: engine/src/renderer/opengl/gl_shader.c, gl_renderer.c, engine/include/renderer/frame_data.h                                                                                                                                                                                                              │
│                                                                                                                                                                                                                                                                                                                 │
│ ---                                                                                                                                                                                                                                                                                                             │
│ 2. Vulkan Backend Missing Depth Testing + Blocking Synchronization                                                                                                                                                                                                                                              │
│                                                                                                                                                                                                                                                                                                                 │
│ Why it's #2: Without depth testing, 3D rendering is fundamentally broken on the Vulkan path. The blocking sync patterns will stall the CPU every frame.                                                                                                                                                         │
│                                                                                                                                                                                                                                                                                                                 │
│ What's happening:                                                                                                                                                                                                                                                                                               │
│ - vk_pipeline.c:86 — // TODO: Depth and stencil testing — no depth buffer at all                                                                                                                                                                                                                                │
│ - vk_renderer.c:233 — vkWaitForFences(..., UINT64_MAX) blocks CPU indefinitely waiting for GPU                                                                                                                                                                                                                  │
│ - vk_buffer.c:112 — vkQueueWaitIdle(q) serializes all GPU work during buffer uploads (vertex, index, uniform buffer creation)                                                                                                                                                                                   │
│ - No pipeline cache (VkPipelineCacheCreateInfo not used)                                                                                                                                                                                                                                                        │
│                                                                                                                                                                                                                                                                                                                 │
│ What to fix:                                                                                                                                                                                                                                                                                                    │
│ 1. Add depth/stencil attachment to render pass and pipeline (this is table-stakes for 3D)                                                                                                                                                                                                                       │
│ 2. Use proper double/triple buffering — the fence wait is correct in concept but consider timeout + fallback instead of infinite block                                                                                                                                                                          │
│ 3. Batch buffer transfers with a transfer command buffer + fence instead of vkQueueWaitIdle per upload                                                                                                                                                                                                          │
│ 4. Add pipeline cache for faster startup on subsequent runs                                                                                                                                                                                                                                                     │
│                                                                                                                                                                                                                                                                                                                 │
│ Files: engine/src/renderer/vulkan/vk_pipeline.c, vk_renderer.c, vk_buffer.c                                                                                                                                                                                                                                     │
│                                                                                                                                                                                                                                                                                                                 │

│ 3. Texture Data Stuck in RAM After GPU Upload                                                                                                                                                                                                                                                                   │
│                                                                                                                                                                                                                                                                                                                 │
│ Why it's #3: Every texture consumes memory twice — once in your asset arena (CPU), once on the GPU. As you add more textures/models, this becomes a real memory problem. The asset arena also can't free individual items, so this memory is permanently occupied.                                              │
│                                                                                                                                                                                                                                                                                                                 │
│ What's happening:                                                                                                                                                                                                                                                                                               │
│ - texture.c:33-34 — pixel data is copied into the asset arena, uploaded to GPU, but the arena copy stays forever                                                                                                                                                                                                │
│ - Comment in GL text code acknowledges: "Potentially free the asset, since its already generated a gl texture... However, currently asset system uses arena allocator, so i can't free specific assets :/"                                                                                                      │
│ - asset_system_load_all() (asset.c:151-177) blocks the main thread synchronously — no streaming, no prioritization                                                                                                                                                                                              │
│                                                                                                                                                                                                                                                                                                                 │
│ What to fix:                                                                                                                                                                                                                                                                                                    │
│ 1. Separate texture pixel data from asset metadata — use a temporary arena (or even stbi_load directly into a staging buffer) that gets released after GPU upload                                                                                                                                               │
│ 2. Keep only the rl_texture metadata (width, height, GPU handle) in the asset arena                                                                                                                                                                                                                             │
│ 3. Longer-term: add async asset loading with a loading queue + transfer thread for streaming                                                                                                                                                                                                                    │
│                                                                                                                                                                                                                                                                                                                 │
│ Files: engine/src/asset/texture.c, asset.c                                                                                                                                                                                                                                                                      │
│                                                                                                                                                                                                                                                                                                                 │

│ 4. Frame Data Structure Limits Scalability                                                                                                                                                                                                                                                                      │
│                                                                                                                                                                                                                                                                                                                 │
│ Why it's #4: The current rl_frame_data is a flat pointer+count for each category. The game stack-allocates arrays and fills them manually. This works now but becomes painful as scene complexity grows.                                                                                                        │
│                                                                                                                                                                                                                                                                                                                 │
│ What's happening:                                                                                                                                                                                                                                                                                               │
│ - frame_data.h — meshes, lights, text are separate raw arrays with manual count tracking                                                                                                                                                                                                                        │
│ - Game code (game.c) stack-allocates rl_frame_mesh frame_meshes[SCENE_MESH_COUNT] — fixed at compile time                                                                                                                                                                                                       │
│ - Only one primitive type (RL_FRAME_PRIMITIVE_CUBE), only one point light actually used by GL backend (gl_renderer.c:46-51 — hardcoded fallback light, only reads point_lights[0])                                                                                                                              │
│ - No material/texture binding per mesh — color is a vec3, no texture reference                                                                                                                                                                                                                                  │
│ - Text rendering recalculates all glyph vertices every frame even if text hasn't changed                                                                                                                                                                                                                        │
│                                                                                                                                                                                                                                                                                                                 │
│ What to fix:                                                                                                                                                                                                                                                                                                    │
│ 1. Use frame arena for frame data arrays instead of stack allocation (already have frame_arena)                                                                                                                                                                                                                 │
│ 2. Add material/texture ID to rl_frame_mesh so meshes can reference different textures                                                                                                                                                                                                                          │
│ 3. Support multiple lights properly in shaders (uniform buffer array or SSBO)                                                                                                                                                                                                                                   │
│ 4. Cache text vertex data — only regenerate when text content changes                                                                                                                                                                                                                                           │
│                                                                                                                                                                                                                                                                                                                 │
│ Files: engine/include/renderer/frame_data.h, engine/src/renderer/opengl/gl_text.c, engine/src/renderer/vulkan/vk_text.c                                                                                                                                                                                         │

Testing Gaps in Critical Paths                                                                                                                                                                                                                                                                               │
│                                                                                                                                                                                                                                                                                                                 │
│ Why it's #5: You have good unit tests for memory/arena/events/config, but the systems most likely to break have zero test coverage. When you refactor the renderer or add features, you'll be flying blind.                                                                                                     │
│                                                                                                                                                                                                                                                                                                                 │
│ What's missing:                                                                                                                                                                                                                                                                                                 │
│ - No hot reload integration test — the reload path (realm_app_loader.c:174-236) handles state migration, version checking, DLL swapping — all untested                                                                                                                                                          │
│ - No renderer smoke test — ~2000+ lines of Vulkan/GL code with no automated validation                                                                                                                                                                                                                          │
│ - No input stress test — input system drops events if two rapid presses happen in one frame (only tracks current/previous state, no queue)                                                                                                                                                                      │
│ - No performance benchmarks — no way to track if a change regresses frame time                                                                                                                                                                                                                                  │
│                                                                                                                                                                                                                                                                                                                 │
│ What to fix:                                                                                                                                                                                                                                                                                                    │
│ 1. Add a headless render test — initialize renderer, submit one frame of data, verify no crash                                                                                                                                                                                                                  │
│ 2. Add hot reload test — simulate module reload with state version change, verify state reset                                                                                                                                                                                                                   │
│ 3. Add an input buffering queue if you plan on fast-paced gameplay (fighting games, rhythm games)                                                                                                                                                                                                               │
│ 4. Add a simple frame time benchmark using Tracy zones you already have instrumented                                                                                                                                                                                                                            │
